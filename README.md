# 수학질문방 iOS 앱

[수학질문방](https://suhakjilmoon.pages.dev) 을 아이폰 앱으로 다시 만든 것이다.
SwiftUI 로 짠 네이티브 앱이고, 사이트를 웹뷰로 감싼 것이 아니다.

사이트와 **같은 Supabase** 를 본다. 주소도 anon 키도 같다.
그래서 사이트에서 가입한 사람이 같은 아이디와 비밀번호로 앱에 로그인하고,
푼 기록과 성적이 양쪽에 그대로 보인다. 사이트와 앱이 동시에 살아 있어도 된다.

**표와 정책은 하나도 바꾸지 않았다.** 권한은 서버의 RLS 와 `is_admin()`, `is_root()`
가 판정하므로 앱을 새로 짜도 규칙이 그대로 따라온다.

---

## 무엇이 들어 있나

| 탭 | 화면 |
|---|---|
| 홈 | 인사, 오늘의 문제, 새 글, 공지와 스피드 연산으로 가는 길 |
| 칼럼 | 목록과 글. 회원만 볼 수 있고 비회원에게는 자물쇠 안내가 뜬다 |
| 시험 | 레벨테스트와 오늘의 문제, 응시와 채점 결과, 정답률 |
| 모의 | 모의고사 성적과 등급 흐름, 수능 시간표대로 재는 시간 재기 |
| 기록 | 푼 시험과 오답노트 |

탭에 없는 것은 홈이나 계정에서 들어간다. 공지사항, 스피드 연산과 랭킹,
계정(비밀번호, 채팅방 닉네임, 탐구 과목, 탈퇴), 그리고 관리자다.

관리자는 칼럼과 공지 쓰기, 출제와 채점, 현황과 활동 기록을 본다.
회원 관리는 더 위 권한에서만 보이고, 그 권한을 가리키는 말은 화면 어디에도 쓰지 않는다.

### 사이트에는 있고 앱에는 없는 것

- **글번호로 앱 열기.** 카톡으로 받은 `mathroom.app/column/110001` 같은 링크를
  앱이 받으려면 유니버설 링크가 필요하고, 애플 개발자 계정이 있어야 설정된다
- **본문에 사진과 수식이 든 글쓰기.** 앱의 글쓰기는 글만 받는다.
  사이트 편집기는 굵게와 색, 사진, 수식 칩까지 넣는데 그걸 앱에서 다시 만들면
  저장 모양이 어긋나기 쉽다. 그런 글은 사이트에서 쓴다

## 어떻게 만들어지나

```
project.yml                XcodeGen 설정
        │
        │  xcodegen generate      (맥)
        ▼
  Suhak.xcodeproj
        │
        │  xcodebuild             (맥에서만 된다)
        ▼
      Suhak.app / ipa
```

**아이폰 앱은 윈도우에서 컴파일이 안 된다.** `.github/workflows/ios.yml` 이
깃허브가 빌려주는 맥(`macos-15`)에서 빌드하고, 시뮬레이터를 켜서 화면을 찍는다.

`.xcodeproj` 를 저장소에 넣지 않는 이유는 윈도우에서 손으로 못 고치기 때문이다.
파일 하나 추가할 때마다 수천 줄짜리 pbxproj 를 건드려야 하는데 실수하면 통째로 안 열린다.
`project.yml` 은 `Sources` 폴더를 통째로 가리켜서 파일을 더해도 고칠 것이 없다.

## 화면 보기

윈도우에서는 SwiftUI 를 띄워볼 수 없다. 그래서 CI 가 시뮬레이터를 켜고 찍어
`screenshots` 가지에 올린다. 로그인 없이 이렇게 받는다.

```
https://raw.githubusercontent.com/qkfmswlrma/studyapp/screenshots/01-home.png
```

시뮬레이터에는 손가락이 없어서 목록을 눌러 들어갈 수 없다.
깊은 화면은 앱이 실행 인자를 보고 스스로 연다 (`Sources/App/Launch.swift`).

```bash
xcrun simctl launch <기기> app.mathroom.suhakjilmoon --tab 2 --open exam-take
```

**빌드가 진짜 됐는지 의심스러우면 `screenshots` 가지의 커밋을 본다.**
빌드가 깨지면 화면이 안 찍혀서 가지가 옛 커밋에 머문다.

## 폴더

| 경로 | 무엇 |
|---|---|
| `project.yml` | XcodeGen 설정. 여기서 붙여 쓰는 것과 앱 설정을 정한다 |
| `Sources/App/` | 앱 시작, 탭 구성, 실행 인자 |
| `Sources/Core/` | Supabase 붙이기, 자료 모양, 채점, 등급컷 계산, 앱 상태, 색과 유리 |
| `Sources/UI/` | 수식 그리기와 본문 조각 배치 |

| `Resources/Assets.xcassets` | 아이콘과 색 |
| `scripts/ci-run.sh` | 실패한 명령의 오류를 주석으로 남긴다 |
| `HANDOFF.md` | 작업 인수인계. **고치기 전에 읽을 것** |

## 지금 상태와 앞으로 필요한 것

맥에서 컴파일되고, 시뮬레이터에서 진짜 Supabase 에 붙어 화면이 뜨는 것까지 확인했다.
깃허브 액션이 만드는 `.ipa` 는 **서명이 없어서** 그대로는 아이폰에 못 넣는다.

**만드는 사람은 윈도우를 쓴다.** 그래서 맥이 필요한 길과 아닌 길을 갈라 적는다.

| 하고 싶은 것 | 맥 | 필요한 것 |
|---|:---:|---|
| 화면 확인 | 없어도 됨 | CI 가 찍어 `screenshots` 가지에 올린다 |
| 내 아이폰에 넣어보기 | 없어도 됨 | 윈도우용 Sideloadly 나 AltStore + 무료 애플 ID |
| 남에게 나눠주기(TestFlight) | 없어도 됨 | 유료 개발자 계정. 서명은 CI 의 맥이 한다 |
| 앱스토어 출시 | 없어도 됨 | 유료 개발자 계정 + 심사 |

### 윈도우에서 아이폰에 넣기

Actions 에서 `iOS 빌드` 를 열고 `Run workflow` 에 `release` 를 켜서 돌리면
서명 없는 `.ipa` 가 나온다. 그걸 Sideloadly 에 끌어다 놓고 애플 ID 를 넣으면
무료 계정으로 서명해서 아이폰에 넣어준다. 윈도우에 애플 공식 iTunes 가 있어야 한다.

**7일마다 다시 넣어야 하고 앱 세 개까지만 된다.** 무료 계정의 제약이라 어쩔 수 없다.

### 윈도우에서 TestFlight 까지 가기

맥을 사거나 빌릴 필요가 없다. **서명을 CI 의 맥에서 시키면 된다.**

1. 아이폰의 Apple Developer 앱으로 개발자 프로그램에 가입한다.
   본인 확인 때문에 이 단계만 iOS 기기가 필요하다
2. App Store Connect 에서 API 키(`.p8`)를 받는다. 윈도우 브라우저로 된다
3. 그 키를 깃허브 저장소 비밀값에 넣는다
4. 워크플로에 fastlane 단계를 더해 인증서와 프로비저닝을 CI 에서 만들게 한다

예전에는 인증서를 만들 때 맥의 키체인이 필요했지만 지금은 API 키로 대신한다.
번들 아이디는 `app.mathroom.suhakjilmoon` 이다.

사이트를 그대로 감싸기만 한 앱은 애플이 반려하기도 하는데(심사 지침 4.2),
이 앱은 화면을 네이티브로 다시 만들었으므로 그 문제는 해당되지 않는다.

## 왜 이렇게 했나

**사이트 저장소를 고치지 않는다.** 앱 때문에 사이트 코드에 앱 전용 분기가 끼면
사이트와 앱이 서로를 갉아먹는다. `../수학` 폴더는 읽기만 한다.

**숫자를 앱에서 계산하지 않는다.** 정답률은 `exam_question_stats` 와 `exam_stats_all`
이 준 값을 그대로 쓴다. 학생은 남의 제출을 못 읽어서 앱에서 세면 자기 것만 반영된다.
채점 규칙과 등급컷 계산도 사이트와 같은 식을 쓴다. 화면마다 다른 숫자가 나오면 안 된다.

**유리는 떠 있는 것에만 쓴다.** 리퀴드 글래스는 뒤에 있는 것을 굴절시키는 물건이라
굴절시킬 내용이 있어야 유리로 보인다. 읽을 것은 또렷한 판에 두고, 탭 막대처럼
그 위에 떠 있는 것만 유리로 한다. 화면을 통째로 유리로 만들면 허연 판만 겹친다.
